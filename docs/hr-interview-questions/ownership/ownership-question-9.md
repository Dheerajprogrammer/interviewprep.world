# How do you prioritize competing work?

## Answer

Ownership examples show how you noticed a problem, made a decision, involved the right people, and delivered a result. Be candid about constraints and what you would improve next time.

For **How do you prioritize competing work?**, start with the rule or behaviour, then anchor it in a small realistic example. Distinguish the default approach from the exceptions and name the observable outcome: correctness, maintainability, accessibility, performance, or security.

## Example

```text
Situation: A release was at risk because a dependency changed late.
Action: I surfaced the risk, proposed a fallback, and coordinated a scoped release.
Result: We met the date without compromising the critical workflow.
```

Ownership means making the next safe action clear, not silently taking every task yourself.

## How to structure your answer

1. Define the concept in one or two sentences.
2. Explain when you would use it and when you would choose an alternative.
3. Walk through a small example, including an edge case.
4. Close with how you would test or measure the result.

## Common mistakes

- Repeating a definition without connecting it to real code.
- Treating an optimization or abstraction as a default rather than a trade-off.
- Omitting lifecycle, error, cleanup, accessibility, or testing considerations when they apply.

## Follow-up prompts

- What failure mode would you expect if this were implemented incorrectly?
- How would you test this behaviour?
- What changes when the feature must scale to a larger application or team?

## Interview tip

For this easy-level question, narrate your assumptions before coding. Interviewers can assess reasoning from a clear, bounded example much better than from a list of APIs.
